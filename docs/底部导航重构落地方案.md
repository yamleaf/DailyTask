# 被控端（DailyTask）底部悬浮导航重构 — 落地方案

> 目标：引入底部悬浮导航（3 类：远程 / 任务 / 设置），将「远程控制」从「设置」中提升为一级导航，默认落地页为「任务」（原 `MainActivity`）。
> 设计基座对齐控制端（DailyController）的悬浮卡片底部导航样式，并落实此前提出的统一令牌 / 组件 / 状态语义。

---

## 1. 导航架构决策

| 项 | 决策 |
|----|------|
| 导航形态 | 底部**悬浮卡片**导航（MaterialCardView 包裹 BottomNavigationView），视觉对齐控制端 `activity_device_control` |
| 顶级分类 | 3 类：**任务 / 远程 / 设置** |
| 默认落地 | **任务**（原 `MainActivity` 内容），即 App 启动首屏 |
| 远程控制归属 | 从「设置」中**移除**，升级为一级导航 Tab |
| 次级页 | 任务配置 / 消息渠道 / 指令 / QA 等仍保持独立 Activity，由各 Tab Fragment 启动 |

### 落地路径（两阶段，均可独立回滚）
- **Phase 1（本方案优先交付，低风险）**：3 个顶级屏（`MainActivity` / `RemoteControlActivity` / `SettingsActivity`）各自 `<include>` 同一份 `bottom_nav_bar.xml`，各自维护选中态。**不改导航模型**，不动 Activity 结构。
- **Phase 2（理想态，后续）**：合并为单 Activity + `NavHost` Fragment（`MainActivity` 为宿主，startDestination=任务），3 屏转为 Fragment。需将 Activity 逻辑迁移至 Fragment，工作量中等但架构最干净，与控制端完全一致。

---

## 2. 底部导航栏组件规格

| 规格 | 值 |
|------|----|
| 容器 | MaterialCardView，圆角 **24dp**，elevation **6dp**，margin **12dp**，背景 `md_surface`（半透明可选） |
| 内容 | Material3 `BottomNavigationView`，`labelVisibilityMode=labeled` |
| 选中指示 | `Widget.Material3.BottomNavigationView.ActiveIndicator`（品牌色药丸） |
| 着色 | `itemIconTint` / `itemTextTint` = `bottom_nav_color` selector（选中=`md_primary`，未选=`md_onSurfaceVariant`） |
| 菜单项 | 任务 / 远程 / 设置，各带 M3 描边图标（24dp）：任务=`ic_list`，远程=`ic_cloud`，设置=`ic_settings` |
| 默认选中 | **任务** |

```xml
<!-- res/menu/bottom_nav_main.xml -->
<menu>
  <item android:id="@+id/nav_task"    android:icon="@drawable/ic_list"   android:title="任务"/>
  <item android:id="@+id/nav_remote"  android:icon="@drawable/ic_cloud"  android:title="远程"/>
  <item android:id="@+id/nav_settings" android:icon="@drawable/ic_settings" android:title="设置"/>
</menu>
```

## 3. 各 Tab 内容映射与改造

### 3.1 任务 Tab（默认落地）
- **源**：原 `MainActivity`（每日任务主页）
- **保留**：顶部信息卡（刷新倒计时 + 提示 + 启动按钮）、任务列卡 + `EmptyView`、`maskView` 伪息屏遮罩
- **优化**：
  - 倒计时条由 `theme_color` 实色背景改为**浅色底 + 品牌色文字**，降低视觉压迫
  - 任务列 item 套统一列表项/卡片组件
- **Phase 2**：此屏作为 NavHost 的 startDestination

### 3.2 远程 Tab（从设置提升为一级）
- **源**：原 `RemoteControlActivity`
- **保留并强化**：顶部 `heroCard`（状态点 + 最后心跳 + 零耗电说明 + 断线倒计时）—— 这是双端最佳 Hero，**反向输出给控制端概览页**
- **重构原 4 段为 3 个分组卡 + 移除「关于」**：
  1. **绑定操作卡**：生成二维码 / 强制解绑（强制解绑改用统一危险确认对话框，禁止裸跳）
  2. **MQTT 配置卡**：公共开关 / 配置引导 / 服务器 / 用户名 / 密码 / 设备ID / ctl
  3. **Serverless API 卡**：地址 / AppID / Secret / 客户端 / 测试
  4. **删除「关于 → 控制端下载」**：该入口迁出至「设置 → 关于」
- 所有行套统一列表项组件（图标圆角方 + 标题 + 副标题 + 末尾值/箭头）

### 3.3 设置 Tab
- **源**：原 `SettingsActivity`
- **删除**：「远程控制」入口（已是一级导航，重复）
- **保留分组**：通用 / 功能开关（含伪息屏可展开分组）/ 更多
- **新增「关于」分组**：版本号、控制端下载地址（承接远程页迁出的部分）、帮助 / 首次引导入口
- 开关行（图标 + 标题 + 副标题(红字 tip) + switch）替换为**统一列表项组件**，仅视觉统一、交互不变

## 4. 设计基座统一（落实先前建议，引用 DESIGN.md）

| 维度 | 落地 |
|------|------|
| 色板 | 被控端 `theme_color` / `white` / `back_ground_color` 对齐控制端 `md_*` 语义色；`theme_color` 单色补全为整条色阶（primary / container / onPrimary / onPrimaryContainer） |
| 圆角 | 卡片 16 / 统计 12 / 药丸 6 / 图标容器 12 |
| 状态语义 | 统一 **5 态药丸**：在线 / 配对中 / 离线 / 低电量 / 异常（两端共用 `bg_status_pill_*.xml`） |
| 列表项 | 统一组件：图标圆角方 + 标题 + 副标题 + 末尾值/箭头/开关 |
| 深色模式 | 令牌按**浅/深双值**从第一天设计（前移为 P0，非后置） |
| 动效 | 底部导航切换 200ms standard；Tab 内容淡入；`reduced-motion` 全局降级 |
| 无障碍 | 导航项 ≥ 48dp 触控；`contentDescription` 写完整语义；选中态对比度 ≥ 4.5:1 |

> 完整令牌与组件规范见独立 `DESIGN.md`（9 章标准），本方案各屏改造均以其为标尺。

## 5. 文件级落地清单

### 新增
- `res/menu/bottom_nav_main.xml` — 3 个导航项
- `res/layout/bottom_nav_bar.xml` — 悬浮卡片 + BottomNavigationView（`<include>` 复用）
- `res/drawable/bg_bottom_nav_card.xml` — 圆角 24dp / elevation 背景（或直接用 style）
- `res/color/bottom_nav_color.xml` — 选中/未选着色 selector
- `res/drawable/ic_list.xml` / `ic_cloud.xml` / `ic_settings.xml` — M3 描边图标（24dp）
- `res/drawable/bg_status_pill_online.xml` 等 5 个 — 状态药丸背景
- `res/layout/item_list_row.xml` — 统一列表项组件
- `docs/DESIGN.md` — 双端共用设计系统文档（基座）
- Phase 2：`res/layout/fragment_task.xml` / `fragment_remote.xml` / `fragment_settings.xml`、`res/navigation/nav_graph.xml`

### 修改
- `MainActivity` — 底部加 `<include bottom_nav_bar>`，默认选中「任务」
- `RemoteControlActivity` — 移除「关于→控制端下载」段；列表行组件化；强制解绑接统一对话框
- `SettingsActivity` — 删除「远程控制」入口；新增「关于」分组；列表行组件化
- `res/values/colors.xml` / `styles.xml` — 令牌对齐 `md_*`（被控端侧镜像）
- `AndroidManifest.xml`（Phase 2）— `MainActivity` 为 launcher，其余顶级屏取消 launcher intent-filter
- Phase 2：3 个 Activity 改为 Fragment，逻辑迁移至 Fragment（注意 viewBinding / lifecycle / dialog 归属）

### 不变
- `TaskConfigActivity` / `MessageChannelActivity` / `CommandActivity` / `QuestionAndAnswerActivity` — 仍作为次级页由各 Tab 启动
- `dialog_app_picker` / `dialog_custom_app_manager` / `bottom_sheet_layout_select_time` / `window_floating` — 仅套统一圆角/宽度/组件规范，逻辑不变

## 6. 分阶段与回滚边界

| 阶段 | 范围 | 回滚 |
|------|------|------|
| **Phase 1** | 3 Activity 各加 `<include bottom_nav_bar>`，各自维护 selected；远程页去「关于」、设置页去「远程控制」入口 | 每个 Activity 改动独立，删 include + 还原两处删改即完全还原 |
| **Phase 2** | 合并单 Activity + NavHost Fragment | 保留 Phase 1 的 Activity 版本分支可回退；转换前先冻结 Phase 1 产物 |

## 7. 设计 QA 验收标准

- [ ] 三 Tab 切换无白屏、无 Activity 重建闪烁（Phase 1 至少无崩溃、选中态正确）
- [ ] App 启动默认进入「任务」页
- [ ] 「远程」Tab 不含「关于 → 控制端下载」
- [ ] 「设置」Tab 不含「远程控制」入口，且新增「关于」分组含控制端下载
- [ ] 底部悬浮卡片视觉与控制端一致（圆角/阴影/选中指示）
- [ ] 深色模式下导航栏与选中态对比度达标（≥ 4.5:1）
- [ ] 状态药丸 5 态在远程页正确映射
- [ ] 所有列表行使用统一组件，两端观感一致

---

## 8. 风险与注意

1. **Phase 2 Fragment 转换**：`RemoteControlActivity` 长 `NestedScrollView` + 多 dialog，迁移需注意 viewBinding 生命周期与 dialog 归属 Fragment。
2. **令牌替换波及面广**：先抽 `tokens.xml` / `DESIGN.md` 基座，再逐屏替换，避免一次性大改导致难以回滚。
3. **图标缺失**：被控端缺 `ic_list` / `ic_cloud` / `ic_settings` M3 图标，需新增（描边 24dp，与控制端图标风格一致）。
4. **导航默认态**：确保 `MainActivity` 启动即选中「任务」，且从次级页返回回到对应 Tab 而非重置。
