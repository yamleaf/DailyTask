# DailyTask（DT）使用说明

> 适用对象：被控端 DailyTask（包名 `com.pengxh.daily.app`）。  
> 本文按当前 DT 代码路径整理，界面文案以本文描述的最新版本为准；控制端 DailyController 的操作只在与 DT 配对、下发指令时提及。

---

## 1. 先理解四个概念

| 概念 | 含义 |
|---|---|
| 任务 | 一个计划打卡时间点，例如 `09:05:00`。可以附带备注；一天可以有多个任务。 |
| 调度 | 点击「启动」后，DT 按时间顺序等待并逐个执行今天的任务。 |
| 重置 | 每天到达「重置时间」后，DT 把任务列表重新排入新一天的周期；不是刷新网页或重新联网。 |
| 暂停使用 | 设置页里的总开关，开启后停止前台/后台服务、闹钟和远程指令；不是「停止今天的任务」。 |

另外两个容易混淆的词：

- **停止任务**：只停止当前这一轮调度，今天剩下的任务不再执行；明天如果循环任务还开着，重置后仍会自动开始。
- **关闭循环**：关闭「每日自动循环」标志，之后到重置时间不会自动开始，需要手动启动或重新开启循环。

## 快速配置（新用户建议先看这里）

按下面顺序，5 分钟左右即可跑通一次打卡。标「可选」的步骤可日后再补。

### 步骤一：配置目标应用（必需）

路径：**设置 → 打卡设置 → 目标应用**

选择你的打卡应用（钉钉 / 企业微信 / 飞书 / 移动办公 M3，或「自定义应用」填包名）。目标应用需已登录、开启「极速打卡」，且账号不能被其他设备挤下线。

### 步骤二：权限自检并授权（必需）

路径：**设置 → 权限设置 → 基础权限 → 权限自检**

先跑一次自检，按结果逐项处理。至少保证这五项到位，否则后台拉起会受影响：

- 悬浮窗（倒计时 + 后台拉起目标应用）；
- 通知；
- 自启动（国产 ROM 重点）；
- 通知监听（远程指令 / 钉钉通知结果来源依赖它）；
- 电池优化白名单。

各权限用途见下文「2. 使用前准备」的权限清单。

### 步骤三：选择结果来源（必需）

路径：**设置 → 打卡设置 → 结果来源**

- 钉钉 → 选「通知」；
- 其他应用 → 选「截屏」或「无障碍」（Android 14+ 推荐无障碍）。

切换前先打开对应权限，否则会被拦截。

### 步骤四：配置息屏 / 伪息屏（建议，二选一）

路径：**设置 → 功能增强 → 伪息屏**

- 想让设备在黑屏蒙层下继续运行 → 开启「伪息屏」；
- 想保持真实息屏 → 关闭「伪息屏」，在「屏幕模式」里配置前台无操作后的熄屏行为，并按需调整「息屏保活」。

详见「6.4 功能增强」。

### 步骤五：添加任务并配置参数（必需）

1. 任务页点右下角 `+` 添加任务，设置时间（可加备注）；
2. **设置 → 打卡设置 → 任务配置**：确认重置时间、超时时间、工作日、循环、随机时间等。

详见「4.5 添加/编辑任务」与「8. 任务配置页」。

### 步骤六：启动并试跑一次（必需）

回到任务页点「启动」，观察一次完整打卡，再用「打卡记录」确认结果（成功/超时以记录和消息通知为准）。

### 步骤七：配置 MQTT 并用 DC 绑定（可选，需要远程控制时）

1. 远程页配置 MQTT 服务器 / 被控端用户名 / 密码，点「测试 MQTT 连接」；
2. 开启远程服务；
3. 生成绑定二维码，用 DC 扫码绑定。

详见「5. 远程页详解」。

### 步骤八：配置邮箱通知（可选）

路径：**设置 → 打卡设置 → 消息渠道 → QQ 邮箱**

配置发件箱、授权码、收件箱，点「测试邮件」验证。授权码需在邮箱设置里单独生成，不是邮箱登录密码。详见「6.2 打卡设置 → 消息渠道」。

> 按增强功能逐步展开的完整顺序，可参考文末「11. 推荐配置顺序」。

## 2. 使用前准备

### 2.1 设备与目标应用

- 建议使用一台备用 Android 手机，系统 Android 8 及以上。
- 目标打卡应用必须支持「极速打卡」，并且已经在应用内开启该功能。
- 目标应用需要保持登录状态，账号不能被其他设备挤下线。
- 手机需要能正常联网；如果要远程控制，还需要能访问所配置的 MQTT broker。

### 2.2 首次启动会看到什么

1. **使用须知**：确认软件使用范围后点「知道了」；不想再看到可点「不再提醒」。
2. **权限设置列表**：逐项授权。关键项缺失时，DT 会被系统限制，任务可能无法正常拉起。
3. **悬浮窗缺失警告**：如果悬浮窗权限没开，会再次提示；悬浮窗是打卡倒计时和后台拉起目标应用的重要依赖。

### 2.3 权限清单与用途

| 权限 | 用途 | 建议 |
|---|---|---|
| 悬浮窗 | 显示打卡倒计时、悬浮状态，并在后台拉起目标应用 | 必须开启 |
| 通知 | 任务结果、打卡提醒、异常告警 | Android 13+ 必须开启 |
| 自启动 | 手机重启或被系统清理后恢复后台服务 | 国产 ROM 建议开启 |
| 通知监听 | 接收 `DT#` 文本指令；钉钉结果来源也依赖它 | 使用远程指令或钉钉通知模式时必需 |
| 截屏服务 | MediaProjection 截屏，用于结果判定/超时留证 | 使用截屏结果来源时必需 |
| 无障碍服务 | Android 14+ 可做文本/截屏结果判定 | 使用无障碍结果来源时必需 |
| 电池优化白名单 | 降低后台被系统休眠的概率 | 建议加入 |
| Shizuku | 高级自动化、强制停止目标应用、部分登录操作 | 不用高级功能可不装 |

### 2.4 建议先跑一次「权限自检」

路径：**设置 → 权限设置 → 基础权限 → 权限自检**。

它会检查远程指令链路和后台拉起相关的基础权限，并区分：

- 未授权；
- 已授权但通知监听服务没有连接（国产 ROM 自启动拦截是常见原因）。

如果状态异常，按提示去系统设置处理，再回来重新检测。

## 4. 任务页详解

### 4.1 顶部状态卡

| 元素 | 含义 | 是否可点 |
|---|---|---|
| 状态点 | 绿色 = 调度运行中；灰色 = 已停止 | 否，只表示状态 |
| 任务调度 | 当前页面标题 | 否 |
| `xx后重置任务` | 距离下一次每日任务重置的时间；由「重置时间」计算 | 否 |
| 主文案 | 「点击按钮后开始执行任务」「正在执行 x/y 个任务」「今日任务已全部执行完毕」等 | 否 |
| 实际执行 | 当前任务的计划/实际时间、备注（执行中显示） | 否 |
| 额外状态 | 只在偏离默认配置时出现，例如「循环关闭」「跳过节假日」「自定义工作日」 | 否 |
| 打卡记录 | 打开打卡记录列表 | 是 |
| 启动 | 开始执行今天的任务 | 是 |
| 停止 | 停止当前这一轮调度 | 是 |

补充说明：

- 「启动」在「暂停使用」开启时会被拦截，提示先关闭暂停使用。
- 「停止」只停当前这一轮，不会删除任务；如果循环任务开启，下一次重置后仍会自动开始。
- 状态点不是按钮，不能点击切换；启停统一走右侧按钮。

### 4.2 任务卡片的显示内容

每张任务卡片从左到右、从上到下大致是：

| 区域 | 内容 |
|---|---|
| 主时间 | 计划打卡时间，格式 `HH:mm:ss` |
| 备注 | 任务名称；没有备注时留空 |
| 状态胶囊 | 执行中 / 待执行 / 已过点 / 已跳过 / `-` |
| 随机窗口 | 开启随机时间时显示可能的执行区间，例如 `09:05 - 09:34`；关闭时显示「未启用」 |
| 实际执行 | 当天实际执行时间；没有执行记录时显示 `--:--:--` |

链式时间轴：

- 相邻两个任务都已经过点时，中间连线变成琥珀色；
- 执行中的任务节点会有呼吸/扩散效果；
- 整条时间轴只是状态可视化，不影响任务执行。

### 4.3 状态胶囊含义

| 状态 | 含义 | 注意 |
|---|---|---|
| 执行中 | 当前调度正在执行这个任务 | 通常对应顶部「正在执行 x/y」 |
| 待执行 | 在今日计划内，实际时间还没到 | 只是等待，不代表已经开始 |
| 已过点 | 实际时间已经过去 | 可能已经成功，也可能超时；DT 不在这里区分成功/超时 |
| 已跳过 | 今天整体是跳过日 | 节假日、休息日或自定义非工作日，且开启了跳过 |
| `-` | 调度未运行，或该任务不在今天的计划里 | 不代表任务被删除 |

如果你要确认「已过点」到底是成功还是超时，请看：

1. 任务详情里的「实际执行」；
2. **打卡记录**；
3. 消息渠道收到的结果通知；
4. 控制端 DC 的任务页（DC 会区分成功/超时/跳过等更细状态）。

### 4.4 任务卡片操作

| 操作 | 效果 |
|---|---|
| 单击卡片 | 打开编辑弹窗，修改时间/备注；如果卡片处于左滑展开状态，先收起 |
| 长按卡片 | 打开「任务详情」弹层：完整时间、随机窗口、实际执行、备注、复制打卡时间、编辑任务、删除任务 |
| 向左滑动卡片 | 露出「编辑 / 删除」快捷按钮 |
| 点击「编辑」 | 修改任务时间或备注 |
| 点击「删除」 | 二次确认后删除任务 |
| 点击右下角悬浮 `+` | 添加任务；任务列表为空时，可选择「添加任务」或「导入任务」 |

任务执行期间：

- 左侧滑出的编辑/删除按钮会置灰；
- 尝试编辑/删除会被拦截并提示「任务进行中，无法修改/删除」；
- 需要修改时先点顶部「停止」，改完再重新启动。

### 4.5 添加/编辑任务

添加或编辑弹窗里：

- **时间**：选择时、分、秒；
- **备注**：可选，用于区分多个任务；
- **保存**：写入任务列表。

规则：

- 同一个时间点不能重复添加；
- 建议始终用时间选择器录入，避免手工导入的脏时间导致排程异常；
- 修改/删除会同步到远程配置（如果 DC 已绑定，控制端也能看到变化）。

### 4.6 任务执行流程

点击「启动」后，DT 的实际流程是：

1. 读取今天的任务列表，计算每个任务的实际执行时间（开启随机时间时会加入随机偏移）。
2. 按时间排序，逐个等待；临近执行时会安排精确闹钟兜底，防止进程被冻结后漏打。
3. 到点后：
   - 如果屏幕息屏/伪息屏，先亮屏并临时移除蒙层；
   - 如果开启了「任务前清理」并且 Shizuku 已授权，先强制停止目标打卡应用；
   - 拉起配置的目标应用；
   - 启动倒计时，等待结果来源判定打卡成功。
4. 成功：记录实际执行时间，继续下一个任务。
5. 超时：标记打卡超时，按配置发送通知/截图（有截屏权限时），继续下一个任务。
6. 如果遇到以下情况，本场会跳过：
   - 今天是跳过日（节假日/休息日/自定义非工作日）；
   - 任务时间已过，且超过宽限期；
   - 当前已有另一路打卡在进行（远程打卡/上一场未结束）；
   - Shizuku 自动化操作正在进行，避免互相 force-stop/拉起；
   - 目标应用未安装或无法拉起。
7. 当天全部任务结束：显示「今日任务已全部执行完毕」。
8. 到达「重置时间」：如果循环任务开启，进入新一天并重新开始；如果关闭，则等待手动启动。

## 5. 远程页详解

### 5.1 顶部服务卡

| 元素 | 含义 |
|---|---|
| 服务状态 / 大圆形电源按钮 | 开启或关闭远程控制 MQTT 服务 |
| 正在运行 | 服务已启动且 MQTT 已连接 |
| 连接中… | 服务已开启，但 MQTT 还没连上；按钮下方会显示重连倒计时 |
| 已关闭 | 远程服务关闭，MQTT 不连接 |
| 已停止 / 设备ID冲突 | 检测到同账号下另一个设备使用相同设备 ID，服务被暂停 |
| 版本 | 当前构建的 git 短哈希 |
| 已连接 / 未连接 | MQTT 连接状态 |
| 已绑定 / 待扫码 / 未绑定 / 已解绑 | 与控制端的配对状态 |
| 心跳 | 最近一次在线心跳时间 |

按钮：

- **电源按钮**：切换远程服务开关。开启前需要先配置 MQTT 服务器、被控端用户名、密码；配置不完整会提示并保持关闭。
- **立即重连**：服务开启但连接失败时，手动触发一次重连。
- **连接信息**：展开连接配额/连接详情。

### 5.2 绑定操作

| 按钮 | 作用 | 前提 |
|---|---|---|
| 生成绑定二维码 | 生成一次性配对令牌，供 DC 扫码绑定 | MQTT 已配置、远程服务已启动、设备未绑定 |
| 强制解绑 | 解除与控制端的绑定关系 | 需要确认；不会清除本机 MQTT 配置 |

注意：

- 配对二维码有时效（约 60 秒），过期需重新生成；
- 已绑定状态下重新绑定，需要先强制解绑；
- 强制解绑只解除绑定关系，服务器/用户名/密码仍保留，下次绑定不用重填。

### 5.3 MQTT 配置

| 项目 | 说明 |
|---|---|
| 公共 MQTT（临时使用） | 使用公共 broker 快速测试；不建议长期使用，安全性和稳定性有限 |
| MQTT 配置引导 | 查看如何获取 broker 配置 |
| MQTT 服务器 | broker 地址，例如 `tcp://host:1883` 或 `ssl://host:8883` |
| 被控端用户名 | MQTT 账号 |
| 被控端密码 | MQTT 密码 |
| 测试 MQTT 连接 | 用当前参数做一次连接测试 |
| 设备ID | 本机在控制端的唯一标识；如果和其他设备冲突，需要修改 |
| 控制端凭证（ctl） | 与控制端配对/鉴权使用的凭证，按需编辑 |

### 5.4 Serverless API 配置

这一组是**可选的** HTTP 管理能力，用于查看 EMQX Serverless 的客户端/订阅/发布消息，不是普通远程打卡的必需项：

- API 地址；
- AppID；
- AppSecret；
- 在线客户端管理；
- 测试 API 连接。

不配置不影响 MQTT 远程控制和任务调度。

## 6. 设置页详解

### 6.1 外观

| 项目 | 说明 |
|---|---|
| 主题外观 | 深色 / 浅色 / 跟随系统 |

### 6.2 打卡设置

| 项目 | 说明 |
|---|---|
| 目标应用 | 选择钉钉、企业微信、飞书、移动办公 M3，或「自定义应用」填写包名 |
| 消息渠道 | 配置企业微信 webhook / QQ 邮箱，用于结果通知、告警和附件 |
| 结果来源 | 通知 / 截屏 / 无障碍，决定 DT 如何判断打卡是否成功 |
| 无障碍反馈模式 | 使用无障碍结果来源时，选择「文本反馈」或「截屏反馈」 |
| 任务配置 | 重置时间、超时、任务口令、结果关键字、工作日、跳过节假日、循环、随机时间 |
| 更新节假日 | 手动刷新节假日数据（后台也会周期性刷新） |

#### 结果来源怎么选

| 来源 | 适用 | 说明 |
|---|---|---|
| 通知 | 钉钉 | 监听打卡通知，只有钉钉支持 |
| 截屏 | 理论上适用于任何应用 | 使用 MediaProjection；超时/最后阶段可截屏留证 |
| 无障碍 | Android 14+ 推荐 | 文本反馈适合能读到成功文字的应用；截屏反馈适合读不到文字的应用 |

选择结果来源前，必须先在「权限设置」里打开对应权限；否则会提示并阻止切换。

#### 消息渠道

进入「消息渠道」后可以配置：

- 消息标题；
- 企业微信 webhook key，以及「测试推送」；
- QQ 邮箱发件箱、授权码、收件箱，以及「测试邮件」；
- 是否关闭反馈通知。

说明：

- 邮箱授权码不是邮箱登录密码，需要在邮箱设置里单独生成；
- 企业微信 webhook 需要群聊机器人支持；
- 测试按钮只验证消息通道，不执行打卡。

### 6.3 权限设置

#### 基础权限

| 项目 | 说明 |
|---|---|
| 悬浮窗 | 控制悬浮窗显示与状态指示 |
| 通知 | 任务结果、提醒、异常告警 |
| 自启动 | 国产 ROM 开机/后台恢复 |

## 7. 高级设置与 Shizuku

路径：**设置 → 权限设置 → 权限增强 → 高级设置**。

### 7.1 服务权限状态

| 项目 | 含义 |
|---|---|
| Shizuku 通道 | 官方 / 自定义 / 不可用 |
| Shizuku 服务 | 当前 server 进程名 |
| 授权来源 | 未授权 / 用户授权 / ADB 等 |
| 开发者选项 | 是否开启 |
| 无线调试 | 是否开启 |
| ADB 状态 | USB/无线调试状态 |

按钮：

- **刷新**：重新读取 Shizuku 状态；
- **去授权**：向 Shizuku 请求权限；
- **一键授权**：通过 Shizuku 执行 adb，尝试自动授予悬浮窗/通知/自启动/电池白名单/通知监听；
- **终止当前操作**：停止正在执行的 Shizuku 自动化，不影响定时任务调度本身。

### 7.2 清理后台

开关「清理后台」：

- 开启后，在打卡或远程 Shizuku 操作前，先强制停止目标打卡应用；
- 用于清理目标应用缓存/残留页面，降低打卡或自动化失败概率；
- 需要 Shizuku 已授权、服务可用。

### 7.3 五类自动化操作

| 操作 | 用途 |
|---|---|
| 密码登录 | 自动输入账号密码登录 |
| 验证码登录 | 自动处理验证码登录 |
| 身份验证 | 自动完成身份验证步骤 |
| 模拟打卡 | 按配置步骤模拟点击打卡，存在被检测风险 |
| 操作1 | 可重命名的自定义操作 |

每个操作由「步骤」组成。步骤类型：

- 点击坐标；
- 手势滑动；
- 密码输入；
- 验证码输入；
- 验证信息采集；
- 结果判定。

每个步骤可以：

- 从当前屏幕采集坐标；
- 设置执行延迟；
- 删除步骤；
- 对验证码输入设置超时/多格输入。

> 模拟打卡、ADB 点击等自动化方式可能被考勤系统判定为作弊，使用前请确认公司规定和风险。

## 8. 任务配置页

路径：**设置 → 打卡设置 → 任务配置**。

| 项目 | 含义 | 建议 |
|---|---|---|
| 重置时间 | 每天几点开始新一天的任务周期 | 默认 0 点；改后顶部「重置任务」倒计时同步变化 |
| 超时时间 | 拉起目标应用后等待打卡成功的秒数（5~120 秒） | 根据目标应用速度设置，太短会误判超时 |
| 任务口令 | `DT#` 文本指令里的打卡关键词，默认「打卡」 | 改成「签到」后使用 `DT#签到` |
| 打卡结果关键字 | 自定义成功关键字，多个用逗号分隔 | 留空恢复内置关键字 |
| 工作日设置 | 选择哪些星期需要执行，支持自定义日期 | 未选中的星期视为休息日；仅在「跳过节假日」开启时参与判断 |
| 跳过节假日 | 法定节假日/休息日/自定义非工作日是否跳过 | 开启后，跳过日所有任务显示「已跳过」；关闭后每天都执行 |
| 节假日数据 | 查看数据状态/覆盖年份/今日是否节假日 | 数据缺失时可手动更新 |
| 循环任务 | 每日自动循环；**只能通过远程指令修改** | `DT#开启循环` / `DT#关闭循环` |
| 随机时间 | 每个任务在计划时间基础上随机偏移 | 建议开启，降低固定时间特征 |
| 时间范围 | 随机分钟范围 | 例如 30，表示最多向后偏移约 30 分钟 |

随机时间的细节：

- 实际偏移 = 随机分钟（0 到范围-1）+ 随机秒（0~59）；
- 同一天、同一任务、同一设备，多次启动得到的时间是一致的，不会每次重新随机；
- 列表里的「随机窗口」显示的是可能区间，不是固定执行时间；
- 最终以任务卡片的「实际执行」为准。

## 9. 远程文本指令（`DT#`）

前提：通知监听已开启并保持连接；消息必须包含 `DT#` 前缀。

| 指令 | 作用 |
|---|---|
| `DT#执行任务` | 启动循环任务 |
| `DT#终止任务` | 停止当前这一轮任务 |
| `DT#开启循环` | 开启每日自动循环 |
| `DT#关闭循环` | 关闭每日自动循环，直到再次开启 |
| `DT#息屏` | 开启伪息屏 |
| `DT#亮屏` | 退出伪息屏 |
| `DT#考勤记录` | 导出当天考勤记录 |
| `DT#打卡` | 触发一次打卡；如果改了任务口令，用 `DT#新口令` |
| `DT#状态查询` | 查询任务/服务/监听/电量/版本等状态 |
| `DT#截屏` | 截取目标应用屏幕并通过消息渠道返回 |
| `DT#开启远程` / `DT#关闭远程` | 开关 MQTT 远程服务 |
| `DT#开启转移` / `DT#关闭转移` | 开关通知转发 |

说明：

- 指令从通知监听读取，因此通知监听权限/服务连接必须正常；
- 未识别的 `DT#` 文本也会记入指令历史，方便排查误触发；
- DC 控制端的按钮走 MQTT 指令通道，不依赖 `DT#` 文本。

## 10. 最容易混淆的按钮

| 操作 | 实际影响 | 不会影响 |
|---|---|---|
| 任务页「启动」 | 开始今天这一轮调度 | 不会修改任务、不会开启远程 |
| 任务页「停止」 | 停止当前这一轮 | 不会删除任务；循环开启时下次重置仍可能自动开始 |
| 设置「暂停使用」 | 停止前台/后台服务、闹钟、远程指令 | 不是只停任务；关闭开关后恢复 |
| 任务配置「循环任务」关闭 | 到重置时间不再自动开始 | 仍可手动点「启动」 |
| 远程页电源关闭 | 关闭 MQTT 远程服务 | 不影响本地定时调度 |
| 强制解绑 | 解除与控制端的绑定 | 不清除 MQTT 配置、不删除任务 |
| 高级设置「终止当前操作」 | 停止正在跑的 Shizuku 自动化 | 不停止定时任务调度 |
| 高级设置「清理后台」 | 打卡/远程操作前 force-stop 目标应用 | 不会清理 DT 自己 |
| 打卡记录 | 查看任务执行/打卡结果历史 | 不是运行日志，也不是指令历史 |
| 三点菜单「指令历史」 | 查看控制端/`DT#` 指令下发记录 | 不包含完整技术日志 |
| 三点菜单「运行日志」 | 查看 DT 运行/调度/服务技术日志 | 不替代打卡结果记录 |

## 11. 推荐配置顺序

1. 首次启动，完成使用须知和权限列表；
2. 设置 → 打卡设置 → 目标应用，选择实际打卡应用；
3. 设置 → 权限设置，开启通知、自启动、通知监听、电池白名单；
4. 根据目标应用选择结果来源：
   - 钉钉：通知；
   - 其他应用：截屏或无障碍；
5. 配置消息渠道，点「测试推送/测试邮件」验证；
6. 任务页添加至少一个任务；
7. 点「启动」，观察一次完整打卡；
8. 用「打卡记录」确认结果；
9. 需要远程控制时，再配置 MQTT、开启远程服务、生成二维码给 DC 扫码；
10. 最后再开启开机自动调度、桌面宠物、伪息屏等增强功能。

## 12. 常见问题

### 12.1 任务没有执行

按顺序检查：

1. 顶部状态点是否绿色；是否处于「暂停使用」；
2. 「循环任务」是否被关闭（关闭后不会每日自动开始，但可以手动启动）；
3. 今天是否是跳过日：节假日、休息日、自定义非工作日；
4. 任务时间是否已经过点，且超过宽限期；
5. 目标应用是否安装、是否登录、是否开启极速打卡；
6. 悬浮窗/通知/自启动/电池白名单是否被系统回收；
7. 是否被其他打卡或 Shizuku 操作占用而跳过；
8. 查看「运行日志」里是否记录了跳过原因。

### 12.2 DT 显示「已过点」，但没有成功记录

DT 的「已过点」只表示时间已经过去，不区分成功/超时。请查看：

- 任务详情里的「实际执行」；
- 打卡记录；
- 消息渠道的通知/邮件；
- DC 任务页的更细状态。

### 12.3 DC 任务页全是「已跳过」

通常是 DT 判断今天是跳过日（节假日/休息日/自定义非工作日）。检查：

- 任务配置 → 跳过节假日；
- 工作日设置；
- 节假日数据。

### 12.4 远程页一直「连接中」

检查：

1. MQTT 服务器/用户名/密码是否正确；
2. 手机网络是否能访问 broker；
3. 点「测试 MQTT 连接」；
4. 设备 ID 是否与其他设备冲突；
5. 远程服务是否被「暂停使用」拦截。

### 12.5 生成二维码失败

常见原因：

- 未配置 MQTT 服务器/用户名/密码；
- 远程服务未启动；
- 设备已经绑定，需要先强制解绑；
- 二维码过期，需要重新生成。

### 12.6 三点菜单不见了/不明显

三点菜单在任务页右上角，包含「指令历史 / 运行日志」。如果图标和深色头部融在一起，确认当前版本已使用白色溢出图标。

### 12.7 「18 分钟后刷新」是什么意思

它不是刷新网络，而是距离**每日任务重置**还有 18 分钟。实际值由「任务配置 → 重置时间」计算；当前版本文案已改为「18 分钟后重置任务」。

## 13. 安全与风险提示

- 本软件仅用于自己有权操作的设备；不要用于未经授权的设备或账号。
- 模拟打卡、ADB 点击、修改定位等自动化方式可能被考勤系统判定为作弊，风险由使用者自行承担。
- 公共 MQTT broker 仅适合临时测试，长期使用建议自建 broker 并设置账号密码。
- 正式依赖前建议先试跑几天，确认目标应用、权限、网络和结果判定都稳定。
